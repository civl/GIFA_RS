## 实战抓到的 7 个问题

### 1. 独占全屏根本无法覆盖（没法修，只能要求）

游戏全屏时 `WindowFromPoint` 在我们自己的窗口坐标上返回**游戏窗口**：
独占全屏接管显示输出，置顶也没用，鼠标点击也不会传给别的窗口。

→ 产品要求：游戏必须用「窗口化」或「无边框窗口」。UI 里应给出这条提示（待做）。

### 2. 拖不动：`-webkit-app-region: drag`

原版 CSS 的标题栏写了 `-webkit-app-region: drag`（Electron 特性）。
**WebView2 没有宿主实现它，但 Blink 仍然吞掉该区域的鼠标事件** —— 页面收不到 mousedown。

→ 改成 `no-drag`，拖动由外壳驱动。

### 3. 第一次点击只激活、不派发事件

`WS_EX_NOACTIVATE` 的宿主窗里，WebView2 **不派发 DOM 鼠标事件**。
用户观察到的现象非常典型：*先点一下最小化（激活窗口），之后拖标题栏就正常了*。

→ 去掉 `NOACTIVATE`（允许激活），并在 `WM_ACTIVATE` 时若左键按着且光标在拖动区，
**立刻开始拖动**，做到"一次点击就能拖"。
代价：点浮窗会把焦点从游戏拿走（WebView2 的取舍，Electron 版没这问题）。

### 4. 拖动区坐标没换算

页面上报的拖动区是**窗口内**坐标，轮询拿到的光标是**屏幕**坐标，差一个窗口原点。
表现是"按下了但判定不在区域内"。

→ 加窗口原点偏移。

### 5. `RegisterHotKey` 自动重复

按住 `Alt+I` 时 Windows 连续发 `WM_HOTKEY`，实测 **8 秒内触发了 10 次**，
窗口在沉浸模式里反复横跳。

→ 同一动作 300ms 内只认一次（`RegisterHotKey` 拿不到 keyup，只能按时间；
钩子键仍用"按下集合"去重）。

### 6. 截屏截到的是"压在上面的窗口"

浮窗被盖住时 GDI 按屏幕坐标取像素，取到的是游戏画面 —— 识别于是把游戏里的青色
（原神的水、特效）当成小地图箭头，日志里出现过 `cyan=0.1517 arrow=321°` 这种假方位。

→ 每次采样前先判定"浮窗是不是真的露着"（`WindowFromPoint` 命中自己），
被盖住就**暂停识别并写日志**。宁可不报，也不要报一个看着有数据、其实是别人画面的方位。

### 7. 置顶会被游戏抢走

游戏会周期性把自己抬到最前。只在"发现自己不是 topmost"时重设不够
（自己标记是 topmost，但对方也是 topmost 且后抬起）。

→ 改成**无条件重新 `SetWindowPos(HWND_TOPMOST)`**，并且被遮挡时立刻抢回来。

## 已知限制（写进产品约束）

- 独占全屏不可覆盖 → 必须窗口化/无边框；
- 点浮窗会夺走游戏焦点（WebView2 行为）；
- GDI 截屏在独占全屏下返回黑帧；
- 手柄只在 XInput 上验证过，其它 API（DS4/DInput）未测；
- 识别仍是占位算法：本次视频里没有小地图，`cyan=0`，所以"识别真实小地图"这一项**没有验证**。
